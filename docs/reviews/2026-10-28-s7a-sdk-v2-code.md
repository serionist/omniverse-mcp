# Review: S7a, the server on MCP SDK v2, with one call to the bridge that raises ToolError

Read from the pack (scope diff without the lock file and the baseline, the author's live smoke script) and the
installed `mcp` 2.3.0's source; the reviewer's probes are `probe_errors.py`, `probe_guards.py` and
`probe_oserror.py` in its scratch folder. Four minors, no round 2; fixed in `c9c6e3e`, after the branch was rebased
onto `b699856` (#23).

Refuted, each from the code or a probe:

- **The scripted rewrite dropped a check:** 42 `bridge_call` sites, the old `_call` sites less each module's
  definition; every `_call` was followed by `_check_error`, no tool read `status` itself, and the only other early
  return was `manage_extensions`'. The three scene tools used `resp` only for the check. Success text is unchanged.
- **A main image that won't decode becomes an error result:** the bridge base64-encodes real PNG bytes; it can't
  happen, nor in the segmentation branches.
- **Other client exceptions get through:** JSON and framing faults already become `ConnectionError`; a bad
  `Content-Length` or non-dict JSON needs a server other than the bridge.
- **The lock:** everything that touches the socket is under it (`request`, `_exchange` with the handshake, the retry
  and `_disconnect`, and `close`); nothing takes it twice. One 120 s call holds the others as long, as v1's blocked
  event loop did; the plan chose serial calls (R3, P3).
- **Work at import, the entry points, `version()`:** the import test and a run confirm nothing happens at import;
  `python -m omniverse_mcp` and the console script run; `version()` works from the editable install and a wheel.
- **Compatibility:** CI passed on every leg; the `MCPServer` keywords exist; `mime_type` reaches the client as
  `image/png`; `ResourceError` arrives as `MCPError` with its message; 41 tools register.
- **The coverage floor:** CI's Linux 3.12 leg measured 76.72% against 76.
- **The serial test:** with the lock a no-op, `most_inside` was 2 in 3 runs of 3.
- **New packages:** `httpx2`, `httpcore2` (BSD-3), `mcp-types`, `truststore` (MIT), `opentelemetry-api`
  (Apache-2.0), pulled in by the pinned `mcp`, all locked.

Not covered: kit-main-thread (no extension code here) and bridge-security (the lock doesn't touch auth; a refusal
names the token's path, never the token).

Improvements:

- `_resource` repeated `bridge_call`: taken; it calls it and turns a `ToolError` into a `ResourceError`, so a
  resource's failure carries the traceback lines too.
- The mock bridge's delay and in-flight count, which nothing read and which can't see two threads on one socket:
  taken, removed, with the PR's line about them.
- A listener that accepts and closes, for a fast unreachable-bridge test: left. A refused port is what a missing Kit
  app looks like; 2 s on Windows is a fair price for testing that case.

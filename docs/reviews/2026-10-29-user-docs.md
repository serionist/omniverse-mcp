# Review: the user docs, for a first setup

A fresh reader went through the docs as four kinds of user: Claude Code with the plugin, another client with uvx, a
headless or scripted Kit, and a developer from a clone. A second agent checked the outside facts the rework states:
each client's config, Claude Code's plugin commands, uvx's caching, Kit's flags and `SimulationApp`, image costs, the
badges. #39 takes the findings below.

## Structure and wording

- **Taken:** the README's order (requirements, install by client, a check, examples, tools, updating, configuration,
  troubleshooting, known issues, security, docs); `docs/SETUP.md` for the detail; "From a clone" into
  `CONTRIBUTING.md`; one name per thing (the server, the bridge, the Kit app); AI_GUIDE.md recast for clients without
  the plugin; a find-a-tool table and the output rule once at the top of TOOLS.md, its internal notes dropped,
  `set_material` under Material Tools as the README groups it; " -- " and em dashes, American spellings; the badges.
- **Kept:** the anchors released files link to (`#install`, `#configuration`, `#the-bridge-token`, ARCHITECTURE's
  `#the-bridge-token`) and every file path PyPI's 0.2.0 page links to.
- **PyPI:** headings there get `user-content-` ids, so a new substitution in `pyproject.toml` points the README's
  in-page links at them.

# Review: the 0.2.0 release PR

Read from the diff, the whole 0.2.0 section as `release.py notes` gives it, the README as PyPI will render it (the
built wheel's description: every image returns an image from raw.githubusercontent.com, every link exists on
`main`), `plugin/README.md`, the setup skill, `docs/releasing.md`, and every place that names a version, with CI's
results on the head (all checks passed, `Package (Linux)`'s `release.py pr` among them). Three minors, fixed in
`9842067`; two improvements taken.

Refuted, each from the repo:

- **The notes' `git pull` and `pip install .` mislead a PyPI user:** they sit under Breaking changes, which concern
  installs from before 0.2.0, every one a clone (0.1.0 was never published); the notes now say so first.
- **An old pip install hides the release:** the only earlier version is 0.1.0, never on an index.
- **The setup skill's "a version not found means this release isn't on PyPI yet" is true only before 0.2.0:** it is
  the gap every release has between merge and publish (R10).
- **PyPI's images point at `main`, not the tag:** #36's design, as `pyproject.toml` says.
- **`uvx omniverse-mcp@latest` leaves the client's unpinned `uvx omniverse-mcp` behind:** uv's docs say a later
  invocation uses the refreshed version.
- **`release.py pr` after the merge:** every later change runs the 0.2.0 check, which passes while the versions stay
  (the gate keeps them equal): stricter, not looser. Its docstring said otherwise and now says so.

Improvements, both taken:

- **British spelling in lines PyPI keeps:** "colour", "visualisation".
- **A line opening the 0.2.0 notes:** the first release on PyPI, and the breaking changes concern a clone from before.
